# 하이닉스 직무 목적과 연구 진행 점검

검토일: **2026-10-04**. 연구 상태: **`RESEARCH_CANDIDATE_NOT_GOVERNED_EVIDENCE`**.

이 문서는 사용자가 요청한 독립 관리 역할의 실제 검토를 남긴다. 목표는 SK하이닉스의 영업·마케팅·상품기획·신제품사업화 학습에 필요한 조사 범위를 넓히고, 수집 결과를 상품과 고객의 문제로 다시 모으는 것이다. 검토 대상은 **하이닉스와 삼성전자의 같은 분기 메모리 관측표**, 이어서 작성한 **AI 기술·업무 조건과 메모리 상품 요구의 연결표**다. 아래에 작업별 실제 판정과 수정 이력을 보존한다. 기업·API·자료의 개수나 근거 없는 완성률로 성과를 판단하지 않는다.

관리 역할은 이번 작업에서 수행한 초기 범위 검토, 연구자에게 전달한 수정 기준, 통합 산출물의 목적 적합성 검토로 구성된다. 상시 모니터, 자동 평가 시스템 또는 Hermes 런타임의 설치·가동을 뜻하지 않는다. [프로젝트의 도구와 역할 경계](../../../00_MASTER/03_WHERE_TO_USE_WHAT.md)에 따라 관리 기능과 특정 실행 도구를 구분한다.

## 목적과 검토 기준

기준 목적은 [상품 고객 직무 학습 문서](sk_hynix_commercial_role_context.md)의 **고객 문제 → 요구 사양 → 관계 주체 → 채택 단계 → 공급 위험 → 직무 질문**이다. [거시 구조](semiconductor_macro_structure.md)의 제품·사업모델·공정·수요시장·지역 축과 [메모리 지표 수집 계약](memory_cycle_signal_plan.md)의 측정 범위도 함께 적용한다.

| 검토 기준 | 통과할 설명 | 수정이 필요한 경우 |
| --- | --- | --- |
| 목적 연결 | 관측이 어떤 상품·고객·구매·공급 질문을 돕는지 제시 | 회사 숫자를 나열하고 직무 질문으로 연결하지 않음 |
| 제품 구분 | DRAM·NAND와 HBM·서버·모바일 등의 공개 범위를 보존 | 전체 DRAM 값을 HBM 값으로 바꾸거나 NAND 칩과 SSD 단위를 혼합 |
| 기간과 공표 시점 | 같은 회계 기간·비교 기준, 실적·전망, 공개일을 분리 | 서로 다른 회계 분기 또는 아직 미공개인 실적을 같은 관측으로 비교 |
| 정의와 단위 | 출하 비트·회사 ASP·재고 장부금액·투자 집행의 범위를 구분 | 재고 금액을 비트 수량, CAPEX를 당기 판매 가능 공급으로 환산 |
| 반론과 공백 | 제품 믹스·평가손실·고객 재고·공정 전환 등 대체 설명과 미공개 항목을 명시 | 단일 지표로 수요 회복·고객 주문·선행성을 확정 |
| 재사용 가능성 | 원문 locator·기간·정의·단위·짧은 발췌·hash로 돌아갈 수 있음 | 재인용 기사만 남기거나 원문 범위보다 넓게 결합 |

판정은 점수가 아닌 작업 판단이다. **CONTINUE**는 현재 범위에서 진행해도 된다는 뜻, **REWORK**는 문서나 자료 정의를 수정해야 한다는 뜻, **DEFER**는 현재 질문에 필요한 근거가 부족하거나 우선순위가 낮아 확대를 미룬다는 뜻이다. 어느 판정도 사람의 Evidence 승인, 사업 권고 또는 선행성 검증으로 승격하지 않는다.

## 초기 범위 판정

**CONTINUE:** 같은 분기의 공급자 공개 자료를 관측표로 만드는 작업은 거시 분류를 실제 수급 설명에 연결하므로 목적에 부합한다. 하이닉스를 기준으로 삼성전자와 비교하되 공개 범위가 다른 항목은 차이를 숨기지 않는다. 비교 가능 항목과 회사 설명만 남는 항목을 함께 제시한다.

| 조사 방향 | 초기 판정과 이유 |
| --- | --- |
| DRAM·NAND 판매 비트와 ASP 직접 공개 여부 | **CONTINUE.** 매출의 물량·단가·제품 믹스를 구분할 질문에 필요 |
| 기말 재고 장부금액과 실제 제품 범위 | **CONTINUE.** 출하와 구매의 차이를 묻는 출발점. 회사 전체 재고를 메모리 재고로 바꾸지 않음 |
| 투자 집행·현금 유형자산 취득·투자 계획의 차이 | **CONTINUE.** 공급 준비와 발표의 차이를 설명하기 위해 정의부터 확인 |
| 모바일·PC·서버 수요와 제품 믹스의 대체 설명 | **CONTINUE.** AI/HBM 중심 설명이 전체 DRAM·NAND를 대표하는지 반론에 필요 |
| 세 번째 업체와 과거 전 기간의 패널 확대 | **DEFER.** 이번 두 업체의 같은 분기·정의 비교를 먼저 완결한 뒤 필요성을 판단 |
| ETF·신규 API 개수·주식 수익률·H1 분석 확대 | **DEFER.** 현재 관측표의 제품·고객 질문을 해결하지 않으며 H1 상태도 별도 |
| Hermes 설치 또는 상시 실행 관리 시스템 | **DEFER.** 이번 독립 검토에 필요한 기능은 현재 역할 분담으로 수행 가능 |

초기 검토 기준은 통합 담당자와 양쪽 회사 조사 담당자에게 전달했다. 회사 전체 재고와 제품별 비트 재고, CAPEX 집행과 현금흐름표의 유형자산 취득을 분리하고, 원문의 `low/mid/high` 표현을 임의 숫자로 바꾸지 않도록 요청했다. 비교의 목적은 업체의 우열 판정이 아니라 **공개 자료로 어떤 질문까지 답할 수 있는지** 확인하는 것이다.

## 통합 전 중간 점검

초기 진행 보고에서는 삼성전자 프레젠테이션에서 bit shipment·ASP 숫자를 찾지 못한 상태였다. 관리 검토는 이미 수집된 공식 실적발표 스크립트의 관련 본문을 별도로 읽었고, 그 안에 DRAM·NAND의 전분기 대비 출하 변화와 ASP 범위 표현이 있음을 확인했다. 따라서 **특정 파일에 없음**을 **회사 자료 전체에서 비공개**로 판단하지 않도록 수정 요청을 전달했다. 스크립트의 다음 분기 전망은 당기 실적과 별도다.

이 확인은 목적에 맞는 발산의 사례다. 새 지표나 업체 수를 늘리지 않고 동일 발표의 다른 공식 자료를 확인해 당초 질문에 필요한 근거를 보완했다. 하이닉스 조사도 회사 뉴스의 정성 설명에서 공식 상세 IR 자료로 조사 범위를 넓혀 같은 제품군의 당기 출하·ASP와 회사 재고·현금 설비 취득을 확보했다. 통합본은 원문의 범위 표현을 임의의 한 값으로 바꾸지 않았다. 조사 담당자의 원문 검토와 통합 담당자의 파일 무결성 확인은 목적 검토와 별도 책임이다.

| 대상 | 현재 검토 상태 | 후속 확인 |
| --- | --- | --- |
| 하이닉스 관측 후보 | **CONTINUE.** 상세 IR 기반의 회사 JSON을 읽고 제품군·기간·범위 표현·미공개 항목 구분 확인 | 뉴스의 정성 설명을 상세 IR 값으로 임의 환산하지 않고 직접 자료를 사용 |
| 삼성전자 관측 후보 | **REWORK 완료.** 스크립트의 당기 출하·ASP 범위 표현이 통합 관측표와 회사 JSON에 반영됨 | 프레젠테이션/스크립트/재무제표의 역할, 실제/전망, 범위 숫자가 분리됨 |
| 삼성전자 재고와 현금 설비 취득 | **CONTINUE.** 공식 프레젠테이션의 기말·분기 열, 연결 재무제표의 반기 누적 범위와 회사 JSON을 확인 | 전체 연결 재고·반기 누적 현금 취득을 메모리 제품 재고·분기 CAPEX로 바꾸지 않음 |
| 통합 관측표와 직무 해석 | **CONTINUE.** 실제 원고를 읽고 네 직무의 질문과 다음 고객·상품 카드 연결 확인 | 같은 날짜만으로 제품 범위가 같다고 처리하지 않고 비교 조건을 명시 |

중간 확인의 원문은 [삼성전자 2026년 2분기 실적발표 스크립트](https://irsvc.teletogether.com/sec/pdf/2026Q2_script_eng.pdf)와 [2026년 상반기 연결 재무제표](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2026_con_quarter02_all.pdf)다. 이번 관리 문서는 이 자료로 고객별 메모리 수량·단가·수요 강도 또는 실제 공급 능력을 판단하지 않는다. 최종 관측표에서 원문 영수증과 연결한다.

다음에는 공급자 숫자를 더 모으는 범위 확대보다 기명 상품·고객 사례로 좁힌다. Intel 인증과 Dell 전시 탑재는 각각의 공개 사건으로 읽고 같은 SKU·실제 구매·일련의 거래였는지는 근거를 확인한다. 관리 검토는 목적과 해석 범위를 확인했으며 원문 바이트의 재현성, 파일 무결성, 독립 회계 감사 또는 예측력 검증을 대신하지 않는다. H1·Gate 6·Evidence 승인 상태도 바뀌지 않는다.

목적관리 담당은 자신이 작성한 검증기의 독립 품질 승인을 맡지 않고, 다른 담당자의 코드와 root의 실제 문서를 읽어 범위를 점검했다. 판정은 **CONTINUE**다. 날짜·중간 저장 복구·현재/이전 원문 해시·임시 workspace 검사는 자료 수집 계약을 지키는 데 직접 필요하다. 신규 API 호출·계정·runtime·상시 수집·H1/Gate 6 승격은 추가하지 않았다. 원문·기존 JSON/manifest와 승인 상태를 보존하고 과거 후속 권고는 당시 기록으로 표시했다.

최종 기술 검증은 root가 구현 커밋의 깨끗한 로컬 clone에서 확인한 **143 tests PASS**, 두 research validator PASS와 실제 issuer capture 한 건의 읽기 전용 재검사 PASS다. 입력 169개 파일의 실행 전후 bytes가 같고 Git 작업 트리도 깨끗했다. 이 결과는 원문 수집의 현재 접근성·경제적 선행성·사람 승인까지 확인한 결과가 아니다.

**다음 작업 하나:** 기존 KOSIS 생산/출하/재고 측정 계약을 무료 metadata/문서로 구체화한다. 정확한 표·항목·KSIC·기준년·단위·조정을 고정하고 한국 HS 교역과 비교 가능한 범위·불가능한 연결을 구분한다. 본 수집·호출 파일럿·DDR5 카드의 이전 보류 상태를 유지한다.

[지표 목적](indicator_collection_purpose.md)의 40개 검토 객체는 유지하면서 실행 규칙을 좁혔다. 다음 경제적 작업은 KOSIS metadata/측정 계약 하나다. 핵심 7개의 중요도는 동시 수집 지시가 아니며 관계 조건 10개·보조 17개는 구체 질문이 있을 때 최소 선택한다. 분석 보류 3개와 필수 검증 전용 항목 3개를 유지하며 모든 관측에 공통 검증을 적용한다. 정부 자금의 약정·의무액까지 현금 단계로 표현한 중간 문구는 지표 감사의 **REWORK**를 받아 약정·기간 의무액·보고기간 지급의 정의를 구분하도록 수정했다.

목적 검토자는 실제 개정본을 재독하고 현재 안내·실행범위 정리에 **CONTINUE**를 판정했다. 문서 감사는 시점 충돌 해소와 로컬 링크를 확인했다. Root 기술 검증에서 원자료·코드·테스트·스키마 221개 파일의 bytes, H1 계약과 타당성·architecture 본문, 날짜별 후보 분류를 보존했고 두 연구 검증기는 PASS였다. 문서 변경에 맞춘 검증이며 전날의 전체 코드 테스트 143개를 이번에 재실행한 결과로 표현하지 않는다.

요청한 전력·소재·금융·항공우주·제품·제조 기능의 연결 구조는 유지했다. 이번 완료는 현재 진입 안내·중복 설명·실행 범위의 정리이며 모든 역사 문서나 불용 기능의 전면 제거를 뜻하지 않는다. H1 Gate 6·정식 Evidence·경제적 선행성·사람 승인 상태는 바꾸지 않았다.

**다음 작업 하나:** KOSIS 한국 반도체 생산·출하·재고의 정확한 표·항목·분류·단위·기준년·조정·공표/개정과 한국 HS 교역의 비교 범위를 정한다. 본 데이터 수집은 계약 확정 뒤 판단한다.

## 영어 개발 방법 조사와 실제 구조 정리 2026년 10월 7일

사용자는 문서 정리만으로 불필요한 설정·구조가 없다고 판단할 수 있는지 다시 물었고, 영어 YouTube·Reddit·GitHub 방법을 먼저 정리한 뒤 적용하도록 지시했다. [구조 필요성 검토](../../reviews/2026-10-07/structure_cleanup.md)에 출처·날짜·영상 구간·도구 범위와 실제 소비처를 기록했다. 경제 지표 수집보다 이번 검토를 먼저 진행했다.

초기 기술·목적 검토는 **CONTINUE**, 전체 불필요 항목 0개 보증은 **REWORK**였다. Sensor와 하위 Protocol 4개는 정의 외 사용처가 없고, 추상/수동 adapter는 같은 payload를 반환하면서 승인 키만 검사했다. 두 adapter 파일을 제거하고 기존 guard를 pipeline의 같은 입력 경계에 합쳤다. 전체 문맥 로드·문서 재생성·Hermes 의무화 지침과 미구현 디렉터리 구조 목록을 현재 소유 문서로 연결하는 짧은 안내로 교체했다. 초기 eval 안내의 승인 후 생성 조건을 선제 생성 의무로 해석하지 않는다.

변경 후 기술·목적 검토자는 실제 파일과 사용처를 다시 확인해 **CONTINUE**를 판정했다. 영상 담당자는 실제 영어 자막과 메타데이터의 날짜·구간·해석을 재검수했다. Root는 두 scenario의 cold replay workspace 31개 파일, 원자료·연구·수행 기록·schema 182개 파일의 동일 구성/bytes와 전체 **144 tests PASS**, 두 research validator PASS를 확인했다. 신규 테스트 하나는 True/False 전역 승인 키 거절과 캐시 결과·Evidence 보존을 확인한다. AI 역할 분담은 모델 간 실험이나 사람 Evidence 승인으로 취급하지 않는다.

새 plugin·skill·hook·runtime·의존성 설정이나 상시 감시는 추가하지 않았다. H1 승인 계약·Gate 6 대기·요청 산업 연결은 유지했다. 이번 결과는 확인된 adapter 계층과 충돌 지침을 정리한 것이며 모든 함수·schema 필드의 필요성까지 검증해 불필요 항목 0개를 보증하지 않는다. 모델·도구·환경·목적 변경 시 관련 방법을 다시 확인한다.

**다음 경제적 작업 하나:** 기존 KOSIS 생산·출하·재고 측정 계약을 구체화한다. 사용자 요구가 코드 구조의 추가 검토로 이어지면 그 범위를 먼저 적용하며, 경제 지표 수집을 자동으로 시작하지 않는다.

## 수요·공급과 양방향 피드백의 적용 상태 점검 2026년 10월 7일

사용자는 반도체를 기준으로 요인을 선별하는 단계적 조사, top-down/bottom-up, ETF·기업 대응의 교차 확인과 예상–실제 피드백이 적용됐는지 물었다. 완료 기준은 관련 문서·JSON의 관계/측정 설계를 실제 관측·코드 소비처와 대조해 준비와 실행을 구분하고, 확인하지 않은 예측 평가를 완료로 표시하지 않는 것이다. 산업 구조·목적, ETF·실물 비교, 코드·시간 갱신을 서로 다른 읽기 전용 검토자에게 맡겼다.

확인된 구조는 상품/기능별 경로, Q1~Q7과 40개 목적 검토 객체, 대체 설명·수집 전제다. 실제 관측에는 기명 사양·사건, 하이닉스/삼성 2026Q2의 제품군 bit·ASP와 회사 범위 재고·현금 투자/계획, BAI 2026-10-01의 단일 보유 snapshot이 있다. 반도체 직접 주문·같은 사업의 자금/설비 사용·통합 역사 패널·ETF 비중 추세는 미확인이다. 회사 전망이 저장돼 있다는 사실은 우리의 사전 예상이나 후속 평가가 수행됐다는 뜻이 아니다.

코드에서 [시간 갱신](../../../src/pipeline.py)은 과거/신규 Evidence·관계·rubric 차이를 보존한다. [memo](../../../src/memo/builder.py)의 가정·반증·다음 관측과 시간 갱신의 decision-variable 변화 설명은 scenario 입력에 의존한다. [지표 목적](indicator_collection_purpose.md)의 기존 본문에 제품 → 요인 → top-down → bottom-up → 금융 교차 질문 → 예상/실제 → 설명 수정의 7단계를 연결했다. 단계마다 실제 적용 범위와 공백을 표시하고, ETF 수량/발행좌수 비교의 조건·회사 전망과 우리의 예상 구분·원 예상 보존·미관측 처리·기준선/추가 정보 검토를 명시했다. 산업의 강화 피드백과 분석의 피드백은 서로 다른 가설/검토 과정으로 구분했다. 새 기록 파일·수집기·설정·학습/Decision Engine을 만들지 않았다.

세 검토자는 실제 추가한 목적 절을 다시 읽고 담당 범위에 **CONTINUE**를 판정했다. 이는 조사 방법과 적용 상태 설명에 대한 판정이며 산업 예측 체계가 완성됐다는 승인이 아니다. Root는 SEC OIEA의 ETF 원문 구조 설명을 재확인하고, 두 research validator PASS·로컬 링크 48개 누락 0·보호 파일 219개의 구성/bytes 동일·허용 문서 2개 diff와 공백 검사를 확인했다. 문서 변경에 맞춘 이번 검사에서 전체 코드 테스트 144개를 재실행하지 않았고, 신규 경제 관측·예측 결과도 계산하지 않았다.
