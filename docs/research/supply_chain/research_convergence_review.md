# 하이닉스 직무 목적과 연구 진행 점검

검토일: **2026-10-04**. 연구 상태: **`RESEARCH_CANDIDATE_NOT_GOVERNED_EVIDENCE`**.

이 문서는 사용자가 요청한 독립 관리 역할의 실제 검토를 남긴다. 목표는 SK하이닉스의 영업·마케팅·상품기획·신제품사업화 학습에 필요한 조사 범위를 넓히고, 수집 결과를 상품과 고객의 문제로 다시 모으는 것이다. 검토 대상은 **하이닉스와 삼성전자의 같은 분기 메모리 관측표**, 이어서 작성한 **AI 기술·업무 조건과 메모리 상품 요구의 연결표**다. 아래에 작업별 실제 판정과 수정 이력을 보존한다. 기업·API·자료의 개수나 근거 없는 완성률로 성과를 판단하지 않는다.

관리 역할은 이번 작업에서 수행한 초기 범위 검토, 연구자에게 전달한 수정 기준, 통합 산출물의 목적 적합성 검토로 구성된다. 상시 모니터, 자동 평가 시스템 또는 Hermes 런타임의 설치·가동을 뜻하지 않는다. [프로젝트의 도구와 역할 경계](../../../00_MASTER/03_WHERE_TO_USE_WHAT.md)에 따라 관리 기능과 특정 실행 도구를 구분한다.

## 목적과 검토 기준

기준 목적은 [상품 고객 직무 학습 문서](sk_hynix_commercial_role_context.md)의 **고객 문제 → 요구 사양 → 관계 주체 → 채택 단계 → 공급 위험 → 직무 질문**이다. [거시 구조](semiconductor_macro_structure.md)의 제품·사업모델·공정·수요시장·지역 축과 [메모리 지표 수집 계약](memory_cycle_signal_plan.md)의 측정 범위도 함께 적용한다.

| 검토 기준 | 통과할 설명 | 수정이 필요한 경우 |
| --- | --- | --- |
| 목적 연결 | 관측이 어떤 상품·고객·구매·공급 질문을 돕는지 제시 | 회사 숫자를 나열하고 직무 질문으로 연결하지 않음 |
| 제품 구분 | DRAM·NAND와 HBM·서버·모바일 등의 공개 범위를 보존 | 전체 DRAM 값을 HBM 값으로 바꾸거나 NAND 칩과 SSD 단위를 혼합 |
| 기간과 공표 시점 | 같은 회계 기간·비교 기준, 실적·전망, 공개일을 분리 | 서로 다른 회계 분기 또는 아직 미공개인 실적을 같은 관측으로 비교 |
| 정의와 단위 | 출하 비트·회사 ASP·재고 장부금액·투자 집행의 범위를 구분 | 재고 금액을 비트 수량, CAPEX를 당기 판매 가능 공급으로 환산 |
| 반론과 공백 | 제품 믹스·평가손실·고객 재고·공정 전환 등 대체 설명과 미공개 항목을 명시 | 단일 지표로 수요 회복·고객 주문·선행성을 확정 |
| 재사용 가능성 | 원문 locator·기간·정의·단위·짧은 발췌·hash로 돌아갈 수 있음 | 재인용 기사만 남기거나 원문 범위보다 넓게 결합 |

판정은 점수가 아닌 작업 판단이다. **CONTINUE**는 현재 범위에서 진행해도 된다는 뜻, **REWORK**는 문서나 자료 정의를 수정해야 한다는 뜻, **DEFER**는 현재 질문에 필요한 근거가 부족하거나 우선순위가 낮아 확대를 미룬다는 뜻이다. 어느 판정도 사람의 Evidence 승인, 사업 권고 또는 선행성 검증으로 승격하지 않는다.

## 초기 범위 판정

**CONTINUE:** 같은 분기의 공급자 공개 자료를 관측표로 만드는 작업은 거시 분류를 실제 수급 설명에 연결하므로 목적에 부합한다. 하이닉스를 기준으로 삼성전자와 비교하되 공개 범위가 다른 항목은 차이를 숨기지 않는다. 비교 가능 항목과 회사 설명만 남는 항목을 함께 제시한다.

| 조사 방향 | 초기 판정과 이유 |
| --- | --- |
| DRAM·NAND 판매 비트와 ASP 직접 공개 여부 | **CONTINUE.** 매출의 물량·단가·제품 믹스를 구분할 질문에 필요 |
| 기말 재고 장부금액과 실제 제품 범위 | **CONTINUE.** 출하와 구매의 차이를 묻는 출발점. 회사 전체 재고를 메모리 재고로 바꾸지 않음 |
| 투자 집행·현금 유형자산 취득·투자 계획의 차이 | **CONTINUE.** 공급 준비와 발표의 차이를 설명하기 위해 정의부터 확인 |
| 모바일·PC·서버 수요와 제품 믹스의 대체 설명 | **CONTINUE.** AI/HBM 중심 설명이 전체 DRAM·NAND를 대표하는지 반론에 필요 |
| 세 번째 업체와 과거 전 기간의 패널 확대 | **DEFER.** 이번 두 업체의 같은 분기·정의 비교를 먼저 완결한 뒤 필요성을 판단 |
| ETF·신규 API 개수·주식 수익률·H1 분석 확대 | **DEFER.** 현재 관측표의 제품·고객 질문을 해결하지 않으며 H1 상태도 별도 |
| Hermes 설치 또는 상시 실행 관리 시스템 | **DEFER.** 이번 독립 검토에 필요한 기능은 현재 역할 분담으로 수행 가능 |

초기 검토 기준은 통합 담당자와 양쪽 회사 조사 담당자에게 전달했다. 회사 전체 재고와 제품별 비트 재고, CAPEX 집행과 현금흐름표의 유형자산 취득을 분리하고, 원문의 `low/mid/high` 표현을 임의 숫자로 바꾸지 않도록 요청했다. 비교의 목적은 업체의 우열 판정이 아니라 **공개 자료로 어떤 질문까지 답할 수 있는지** 확인하는 것이다.

## 통합 전 중간 점검

초기 진행 보고에서는 삼성전자 프레젠테이션에서 bit shipment·ASP 숫자를 찾지 못한 상태였다. 관리 검토는 이미 수집된 공식 실적발표 스크립트의 관련 본문을 별도로 읽었고, 그 안에 DRAM·NAND의 전분기 대비 출하 변화와 ASP 범위 표현이 있음을 확인했다. 따라서 **특정 파일에 없음**을 **회사 자료 전체에서 비공개**로 판단하지 않도록 수정 요청을 전달했다. 스크립트의 다음 분기 전망은 당기 실적과 별도다.

이 확인은 목적에 맞는 발산의 사례다. 새 지표나 업체 수를 늘리지 않고 동일 발표의 다른 공식 자료를 확인해 당초 질문에 필요한 근거를 보완했다. 하이닉스 조사도 회사 뉴스의 정성 설명에서 공식 상세 IR 자료로 조사 범위를 넓혀 같은 제품군의 당기 출하·ASP와 회사 재고·현금 설비 취득을 확보했다. 통합본은 원문의 범위 표현을 임의의 한 값으로 바꾸지 않았다. 조사 담당자의 원문 검토와 통합 담당자의 파일 무결성 확인은 목적 검토와 별도 책임이다.

| 대상 | 현재 검토 상태 | 후속 확인 |
| --- | --- | --- |
| 하이닉스 관측 후보 | **CONTINUE.** 상세 IR 기반의 회사 JSON을 읽고 제품군·기간·범위 표현·미공개 항목 구분 확인 | 뉴스의 정성 설명을 상세 IR 값으로 임의 환산하지 않고 직접 자료를 사용 |
| 삼성전자 관측 후보 | **REWORK 완료.** 스크립트의 당기 출하·ASP 범위 표현이 통합 관측표와 회사 JSON에 반영됨 | 프레젠테이션/스크립트/재무제표의 역할, 실제/전망, 범위 숫자가 분리됨 |
| 삼성전자 재고와 현금 설비 취득 | **CONTINUE.** 공식 프레젠테이션의 기말·분기 열, 연결 재무제표의 반기 누적 범위와 회사 JSON을 확인 | 전체 연결 재고·반기 누적 현금 취득을 메모리 제품 재고·분기 CAPEX로 바꾸지 않음 |
| 통합 관측표와 직무 해석 | **CONTINUE.** 실제 원고를 읽고 네 직무의 질문과 다음 고객·상품 카드 연결 확인 | 같은 날짜만으로 제품 범위가 같다고 처리하지 않고 비교 조건을 명시 |

중간 확인의 원문은 [삼성전자 2026년 2분기 실적발표 스크립트](https://irsvc.teletogether.com/sec/pdf/2026Q2_script_eng.pdf)와 [2026년 상반기 연결 재무제표](https://images.samsung.com/is/content/samsung/assets/global/ir/docs/2026_con_quarter02_all.pdf)다. 이번 관리 문서는 이 자료로 고객별 메모리 수량·단가·수요 강도 또는 실제 공급 능력을 판단하지 않는다. 최종 관측표에서 원문 영수증과 연결한다.

다음에는 공급자 숫자를 더 모으는 범위 확대보다 기명 상품·고객 사례로 좁힌다. Intel 인증과 Dell 전시 탑재는 각각의 공개 사건으로 읽고 같은 SKU·실제 구매·일련의 거래였는지는 근거를 확인한다. 관리 검토는 목적과 해석 범위를 확인했으며 원문 바이트의 재현성, 파일 무결성, 독립 회계 감사 또는 예측력 검증을 대신하지 않는다. H1·Gate 6·Evidence 승인 상태도 바뀌지 않는다.

### 초기 범위 판정

**CONTINUE.** 기술 설명과 상품·고객 조사의 사이를 메우는 공통 연결표가 필요하다고 판단했다. 완료 조건은 업무 조건 → 시스템 병목 → 상품·사양 → 기명 사건 → 공급 조건의 각 연결에서 원문 범위와 공백을 설명하는 것이다. 관측된 변화, 기술 원리, 회사 계획·주장, 시험 결과와 우리의 가설을 구분하도록 통합 담당에게 전달했다.

필요한 발산은 공식 기술자료의 시험 조건, 플랫폼별 구성, 인증·탑재 사건과 공급 제약을 확인하는 범위다. 소프트웨어 최적화·캐시·정밀도·기존 장비 활용은 같은 업무의 상품 요구가 달라질 수 있는 반론으로 포함한다. 산업 기술 전수조사, 미공개 물량 환산, 주식 수익률·선행성, 신규 API와 실행 도구 확대는 **DEFER**다.

AIL01·AIL02의 NVIDIA 추론 글은 2023-11-17의 기술 배경이고 전체 학습 메모리 계산 자료가 아니다. 양자화 문서는 2026-09-26·`c76f4a8`의 PyTorch 맥락, KV 재사용 문서는 2025-09-15·`0c9430e`의 Engine/Executor 맥락으로 기록돼 있다. 두 문서의 기본값·요청 완료 조건을 하나의 최신 구현처럼 합치지 않도록 표 아래 설명을 요청했다. CMX의 2026-03-16 회사 아키텍처 설명도 이 기술 배경과 구분해야 한다. 원고 검토 당시 JSON에는 이 날짜·범위가 이미 보존돼 있었다.

이 단계는 필요한 소프트웨어 반론을 준비한 상태다. 같은 고객·업무·플랫폼에서 그 조건이 실제 메모리 요구와 구매 선택을 바꿨는지는 별도 근거가 필요하다. 반론 조건의 저장을 실제 성능 시험·고객 관측 또는 총시장 수요의 검증으로 표시하지 않는다.

### 최종 판정과 수렴 대상

**최종 목적 판정은 전달받은 개정문 기준으로 CONTINUE다.** 통합 담당은 2023 추론 기술 배경, 2025 Engine/Executor와 2026 PyTorch 문서의 서로 다른 구현, 2026 CMX 회사 설명과 HBF 규격 사건을 구분하는 본문을 작성해 전달했다. 관리 담당은 그 개정문이 중간 REWORK 요청을 해결한다고 판단했다. 실제 본문 적용 여부와 연결 기록·manifest의 참조·해시·파일 검증은 통합 담당이 별도로 확인한다. 이 목적 검토는 데이터 재현성이나 정식 Evidence 승인을 대신하지 않는다.

소프트웨어 반론의 확인 조건과 기명 상품 사건을 함께 놓아 고객의 요구 사양·채택·공급 질문으로 수렴했다. 현재 저장한 것은 그 질문을 검토할 기준과 회사·기술 원문의 범위이며, 같은 고객 구성의 실제 성능·사용량·구매 증가를 검증한 결과는 아니다. 그런 측정이 없다는 이유로 조건을 생략하거나 업계 총수요를 추정해 채우지 않는다.

현재 수렴 대상은 어떤 고객의 어떤 업무 조건이 HBM·호스트 DRAM·SSD 중 어느 요구를 만들고, 인증·구매·납기에서 무엇이 더 필요한지 설명하는 것이다. 소프트웨어·플랫폼 근거의 추가 확인은 그 질문을 해결할 때만 확대한다. 새 API 발급·실행 도구·자동 수집 확대는 계속 **DEFER**다.
