# 공급망 연구의 경제적 목적과 첫 공개 연결 실험

확인 기준일: **2026-10-03**. 상태: **`RESEARCH_CANDIDATE_NOT_GOVERNED_EVIDENCE`**.

**목적 갱신:** 사용자는 이후 하이닉스의 영업·마케팅·상품기획·신제품사업화 직무 준비와 상품·산업 이해를 우선 목적으로 명확히 했다. 학습·지도 범위는 [하이닉스 상품·고객·직무 관점](sk_hynix_commercial_role_context.md)이 소유한다. 아래 내용은 이미 수행한 단일 고객 약정 수집의 경제적 계약으로 보존한다. 상품·고객 연결과 주문서 후속 추적은 당시 권고이며, 현재 수집 순서와 다음 경제적 조사는 [지표 수집 목적](indicator_collection_purpose.md)을 따른다.

이 연구의 목적은 AI 고객의 구매 약정이 공급자의 자금 조달·집행, 칩·시설·전력 확보, 실제 가동·사용, 매출·현금으로 이어지는 과정에서 **공개 자료가 확인하는 연결과 확인하지 못하는 연결을 구분하는 것**이다. 관심 기업 목록이나 지표 수를 늘리는 것보다, 경제적 질문에 답할 수 있는 관측 단위와 근거를 먼저 정한다.

첫 질문은 **“고객 구매 약정으로부터 공급자의 실제 실현을 공개 자료로 어디까지 연결할 수 있는가?”**다. 첫 대상은 **2025-09-23 OpenAI–CoreWeave 추가 주문서에 관한 SEC 공시 한 건**이다. 이는 공개 연결 가능성과 출처 추적성을 점검하는 단일 사례 실험이다. 대표 표본, 선행성 검증 또는 계약 실현율 분석으로 해석하지 않는다.

이 사례는 **2025-09 역사 사건의 추적 가능성 점검**이다. 문서 확인 기준일이 2026-10-03이라고 해서 그날 현재의 OpenAI–CoreWeave 전체 약정·돈흐름이나 이 주문서의 최신 상태를 조사한 것은 아니다.

## 1. 수집 전에 정할 경제적 질문

```text
고객 구매 약정
  → 공급자 자금 조달·현금 집행
  → 칩·시설·전력 확보
  → 설치·수전·가동·실제 사용
  → 서비스 제공·매출 인식·현금 회수
```

화살표는 확인할 연결 후보다. 사업마다 순서가 다르고 계약·설비가 여러 고객을 동시에 지원할 수 있다. 시간상 앞선 사건이나 같은 회사 이름만으로 자금의 출처·용도, 설비 배정 또는 인과관계를 확정하지 않는다.

| 경제적 질문 | 관측 단위와 결과 후보 | 연결에 필요한 공개 근거 | 연결이 부족할 때의 처리 |
|---|---|---|---|
| 고객은 무엇을 약정했는가? | 주문서·계약 버전별 상대 법인, 서비스 범위, 금액의 성격, 기간, 이행·해지 조건 | 계약을 설명하는 공시·공개 exhibit, 변경·해지 공시의 계약 식별정보 | 공시된 최대 금액을 실제 매출·지급액으로 바꾸지 않는다. 가려진 물량·단가·배정은 `KNOWN_UNKNOWN`으로 둔다. |
| 공급자는 자금을 확보하고 집행했는가? | 차입 계약과 실제 인출·현금 수취, 현금 CAPEX, 고객 선수금 수취·잔액 | 차입자·보증인·기간·통화 및 같은 고객/계약의 직접 연결 문구 | 회사 전체 현금흐름은 별도 배경 관측이다. 약정액을 인출액으로, 계약부채 잔액을 현금 수취로 바꾸지 않는다. |
| 필요한 칩·시설·전력을 확보했는가? | 기명 주문·인도·인수, 시설 임차·공사, 전력 서비스 약정·승인 조건 | 고객·제품·부지·계약/프로젝트가 직접 명시된 원문 | NVIDIA 플랫폼 채택, 시설 공급 계약 또는 전체 전력 지표만으로 해당 OpenAI 주문서에 배정됐다고 추정하지 않는다. |
| 실제 서비스 제공이 시작됐는가? | 계약별 서비스 가용·고객 인수·청구 개시; 별도로 시설 가동·실제 부하·이용 | 같은 주문서·고객·시설을 연결하는 공시 또는 공개 자료 | 회사 전체 Active Power, 건물 운영 상태, 계약 MW는 해당 고객의 실제 사용량이 아니다. |
| 매출·현금을 확인할 수 있는가? | 계약·고객 범위가 명시된 매출 인식과 실제 현금 회수 | 해당 고객/계약의 범위와 기간을 확인할 수 있는 원문 | 전체 매출·RPO·고객 집중도·영업 현금흐름을 주문서별 매출·현금으로 배분하지 않는다. 공개되지 않으면 미확인으로 남긴다. |

서비스 가용, 고객 인수, 청구 시작, 매출 인식, 현금 회수는 각각 별도 결과다. 한 결과의 공개 확인이 다른 결과까지 확인한 것은 아니다. 같은 현금이 차입 수취·설비 지급·고객 비용 상환으로 다시 나타날 수 있으므로 서로 다른 흐름을 합산해 “신규 AI 수요”를 만들지 않는다.

## 2. 투자자의 돈과 기업의 돈

| 관측할 돈 | 받는 주체·관측 자료 | 해석 범위 |
|---|---|---|
| ETF 투자자 배분 | 펀드의 보유 수량·발행 주수·NAV; 설정·환매 추정 | 해당 펀드의 증권 배분이다. 보유 비중은 가격과 분모 변화에도 움직인다. 설정은 현물일 수 있으며 구성 기업에 현금이 들어갔다는 뜻이 아니다. |
| 기업의 주식·채무 발행 | 실제 발행기업/차입자, 수취·인출, 조건·기간 | 기업 금융이다. 기업 간 지분투자, 고객 계약, 대출 약정은 다른 관계이며 자금 용도는 공개된 범위만 연결한다. |
| 고객의 서비스·설비 지급 | 고객·공급자·계약·지급 기간, 직접 공개된 현금 수취·지급 | 기업 운영·투자 현금이다. 계약 총액·RPO·미수금·선수금 잔액과 실제 지급을 구분한다. |

ETF 후보 지표는 [기존 수집 계획](collection_plan.md)의 별도 시장 관측층으로 유지한다. 첫 주문서 실험에는 ETF 비중·설정 추정을 계약 이행이나 기업 CAPEX의 근거로 넣지 않는다.

## 3. 첫 실험의 범위와 관측 계약

시작 자료는 [CoreWeave의 2025-09-25 SEC 8-K](https://www.sec.gov/Archives/edgar/data/1769628/000119312525216497/d17274d8k.htm)다. 기존 [관계 지도](../../../data/research/semiconductor_supply_chain/2026-10-03/supply_chain_map_v3.json)의 `openai-coreweave-capacity`는 2025-09-23 추가 주문서, 최대 약 65억 달러와 2031-05-31까지의 조건부 지급약정을 요약한 연구 후보다. 이 요약을 수집·검토의 출발점으로 쓰며, 실제 지급·서비스 개시나 현재 유효 상태를 확인한 것으로 승격하지 않는다. 공개 exhibit 존재 여부와 비공개·삭제 부분도 원문에서 확인한다.

| 항목 | 수집 전 정한 범위 |
|---|---|
| 경제적 질문 | 주문서가 고객의 구매 약정을 무엇까지 공개하며, 그 뒤 실제 실현을 같은 계약으로 연결할 공개 식별정보가 있는가? |
| 모집단 | 위 주문서에 관한 공시 한 건. OpenAI 전체 계약, CoreWeave 모든 고객·시설·차입을 묶은 표본으로 넓히지 않는다. |
| 관측 단위 | 주문서/공시 버전의 원자적 주장과 원문 locator. 후속 자료를 검토하게 되면 같은 주문서·법인·기간·시설의 연결 근거를 따로 기록한다. |
| 입력 식별자 | CoreWeave CIK `1769628`, accession `0001193125-25-216497`, 원문 URL, 주문서 사건일, 문서 종류·버전, 원문에 나온 상대 법인·계약 명칭. 브랜드와 법인을 자동 통합하지 않는다. |
| 시간 계약 | `event_date`는 계약 사건일, `known_at`은 해당 주장이 공개된 것으로 확인 가능한 시점, `retrieved_at`은 이번 수집 시각이다. 기간 값은 측정 기간, 미래 목표는 `target_date`로 따로 둔다. |
| `known_at`의 정밀도 | SEC 제출 메타데이터의 acceptance 시각이 확인되면 시각과 시간대를 보존한다. 날짜만 확인되면 공시일의 day precision과 시각 미확인을 기록하며 자정·현재 수집 시각을 임의로 채우지 않는다. 2025-09-23 사건일을 2025-09-25 공시의 공개 시점으로 쓰지 않는다. |
| 결과 변수 | 우선 결과는 계약 조건의 추출 가능 여부, 직접 연결 식별정보의 존재 여부, 실제 실현을 확인할 수 있는 범위와 gap이다. 서비스 개시·매출·현금은 원문이 각각 직접 확인하는 경우만 별도 후보 결과로 둔다. |
| 자료·처리 | 무키 SEC 공개 원문 보존 → hash·locator·발췌 → 날짜·단위·조건의 분리 → 후보 주장 검토. 수집 성공은 원문 확보와 추적 가능성의 결과다. |
| 구현 경계 | `scripts/collect_customer_commitment.py`의 SEC·issuer 명시적 경로와 `--verify-only`를 구현했다. 결과는 `data/research/customer_commitments/coreweave_openai_20250923/`에 두며 `sources/`, `captures/<hashid>/`의 불변 기록·영수증, 루트 `record.json` 최신뷰·`acquisition.json` 이력, 별도 `acquisition_failures/`를 보존한다. 원문 추출·해시 재검사와 경제적 실현·예측 검증은 구분한다. |
| 종료 기준 | 원문 수집의 성공·실패 상태, 출처 hash·locator, 조건부 약정과 미확인 실현의 구분, 후속 연결에 필요한 자료를 재검토 가능한 형태로 남기면 첫 수집·검토를 마친다. 실현 값이 없다고 계약 실패로 판정하지 않는다. |

첫 수집에서 이후 분기 공시를 전부 수집하거나 결과값을 계산한다고 약속하지 않는다. 후속 검토 후보는 같은 계약을 직접 언급하는 정정·변경·해지·서비스 개시 자료다. 분기 재무·운영 자료는 해당 주문서의 직접 연결이 없으면 **회사 전체 배경**으로만 둔다. 과거 특정 시점의 관측을 재현할 때는 그 시점 이후 공개된 자료를 당시 입력에 넣지 않는다.

## 4. 반증·제외 기준과 공개 공백

첫 실험의 검토 대상은 “조건부 약정이 공개되어 있고 이를 후속 실현과 연결할 정보가 있는가”다. “약정이 반드시 실제 매출로 바뀐다”는 가설을 전제로 두지 않는다.

| 발견할 수 있는 반증·제약 | 처리 |
|---|---|
| 후속 공시가 주문서의 수정·취소·해지·지연·이행 조건 변경을 명시 | 이전 버전과 새 사건을 함께 보존한다. 최대 약정액·기간·상태를 단순 누적하지 않는다. |
| 원문 금액이 상한·조건부이고 실제 제공·가용성에 달림 | 금액 성격·조건을 그대로 기록한다. 확정 당기 매출·현금 또는 현재 가동 규모로 사용하지 않는다. |
| 자료가 다른 계약·고객·시설·기간을 가리킴 | 해당 주문서의 결과에서 제외한다. 경제적으로 관련된 자료라면 별도 배경 후보로만 남긴다. |
| 재무·운영 수치가 회사 전체이고 주문서별 배정이 없음 | 직접 연결로 계산하지 않는다. 고객 비중·물량·GPU 대수·시설 MW·HBM 수요의 임의 배분을 제외한다. |
| 후속 원문에 실제 서비스·매출·현금 수치가 없음 | `KNOWN_UNKNOWN` 또는 추가 원문 확인이 필요한 `TO_VERIFY`로 남긴다. 공개 부재를 미이행·0·취소로 바꾸지 않는다. |
| 수집 실패·접근 제한·문서 형식 오류·누락 | 수집 상태와 경제적 상태를 분리한다. 실패 영수증을 남기고 성공 자료처럼 표시하지 않는다. |
| 같은 공동 발표·공시를 재인용한 자료가 여러 개임 | 중복 근거로 처리한다. 독립 확인 횟수나 계약 건수를 늘리지 않는다. |

결과에는 각 연결을 **계약을 직접 가리키는 공개 근거**, **회사 전체 배경**, **공개 연결 미확인**으로 나눠 설명한다. 이는 후보 연구의 연결 범위 표시이며 기존 Evidence taxonomy·FACT·human-review 상태를 대체하지 않는다. 특정 고객의 실제 전력 사용, GPU 이용률, 서비스별 단가·인수 일정, 주문서별 매출·현금이 비공개이면 그대로 공백으로 남긴다.

## 5. 기존 연구·승인 체계와의 관계

[32개 지표 카탈로그](../../../data/research/semiconductor_supply_chain/2026-10-03/signal_catalog_v2.json)와 [14개 1차 수집 로드맵](../../../data/research/semiconductor_supply_chain/2026-10-03/collection_roadmap_v2.json)은 전체 후보군이다. 이번 목적은 그중 `capital-contract-event-stage`의 한 사례부터 시작해, 공개 근거로 연결할 수 있는 경계를 확인하는 것이다. 자금·시설·전력·이용 지표의 존재만으로 같은 계약의 결과가 확보되지는 않는다.

이 연구 통합과 단일 계약 수집은 H1 24-Track 변경, Gate 6 데이터셋 동결, Strong Inference 또는 정식 Evidence 승인이 아니다. **`main` 병합 역시 연구 자료·코드의 통합이며 gate 승인이나 경제적 결론을 뜻하지 않는다.** Source → Atomic Evidence → Governance Harness → 사람 검토라는 기존 경계를 유지한다. H1 lead/lag·실현율·신호 순위·결과 verdict를 계산하지 않고 H2/H3나 투자·사업 권고를 시작하지 않는다.
