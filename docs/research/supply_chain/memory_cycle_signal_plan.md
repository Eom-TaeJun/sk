# 메모리 수요·공급 사이클과 공개 시그널 수집 계약

기준일: **2026-10-04**. 상태: **`RESEARCH_CANDIDATE_NOT_GOVERNED_EVIDENCE`**.

목적은 SK하이닉스의 영업·마케팅·상품기획·신제품사업화 관점에서 **어떤 고객이 어떤 메모리를 얼마나 필요로 할 수 있고, 구매·공급 일정이 어디서 달라질 수 있는지** 질문을 만드는 것이다. 아래 18개는 공개 관측 후보다. 회사 내부 영업성과 KPI, 검증된 선행지표, 주식 투자 점수 또는 H1 측정 결과가 아니다. 임계값·선행 개월수·전환율을 정하지 않았다.

제품·공정·사업모델·최종시장·지역 분류는 [반도체 산업 거시 구조 기준판](semiconductor_macro_structure.md)을 따른다. 상품·고객의 실제 관계는 [직무 학습 문서](sk_hynix_commercial_role_context.md)와 [HBM3E × GB300 카드](customer_product_cards/hbm_nvidia_gb300.md)에서 확인한다. 기존 [수집 계획](collection_plan.md)의 32개 후보와 H1 Track은 이 문서로 대체하거나 확대하지 않는다.

## 1. 수요와 공급을 같은 숫자로 취급하지 않는 구조

아래 식은 **우리의 측정 설계**다. 실제 입력값이 확보됐다는 뜻이 아니며, 공개되지 않은 고객 물량·수율·CAPA를 추정해서 채우지 않는다.

```text
같은 최종시장·기간의 메모리 탑재 수요
    = Σ(해당 시스템 수량 × 해당 구성의 메모리 용량)

메모리 업체에 대한 구매
    = 시스템 탑재·교체 요구 + 고객의 재고 축적/감축에 따른 구매 조정
      [다른 공급사의 공급, 기존 재고, 구매 시차는 별도]

동일 공정·기간의 제조 잠재력
    = 웨이퍼 투입 × 웨이퍼당 설계상 다이 수(수율 적용 전) × 다이당 비트 × 관련 수율
      [공정·제품 믹스와 후공정 제약별로 나눔]

판매 가능한 공급
    ← 제조 산출 + 기존 재고
    ← 패키징·검사·고객 인증·품질·제품별 배정 조건
```

첫 식은 **정해진 시스템 구성에 필요한 용량**을 세는 방법이다. 서버 출하 대수에 공개된 최대 메모리 용량을 곱하면 실제 구매량이 되지 않는다. 같은 서버에 DRAM과 SSD가 함께 있어도 두 제품군을 별도로 기록한다. HBM은 DRAM의 제품군이므로 전체 DRAM 수요에 HBM을 다시 더해 중복 계산하지 않는다. Gb/GB, 다이/모듈/완성 SSD, 명목/사용 가능 용량과 구성 선택을 보존한다.

AI에서는 워크로드·모델·문맥 길이·동시성·정밀도·소프트웨어와 시스템 구성을 함께 확인한다. 토큰·벤치마크 점수만으로 메모리 구매 비트를 계산하지 않는다. 같은 시스템에서 메모리를 활용하는 정도와 새 시스템을 구입하는 정도는 별도 질문이다. 기존 공급사 시험은 구성별 효과가 다를 수 있음을 보여 주는 사례이며 보편적 환산 계수가 아니다. **SRC-HY26-SSD-WORKLOAD**, HBM 카드의 **SRC-HBM-NV-INFERENCE / SRC-HBM-MLPERF**.

공급 식은 같은 투입 코호트의 잠재 비트 구조이며 공정 처리 시차가 있어 같은 분기 출하량의 식이 아니다. 생산량 관측값도 아니다. **웨이퍼 투입, 다이 밀도, 수율, 판매 가능한 패키지 수, 특정 고객 배정량**이 공개되지 않으면 `KNOWN_UNKNOWN`으로 둔다. HBM·일반 DRAM의 공정·패키징·제품 믹스가 달라질 수 있다는 조사 질문을 세울 수는 있지만, 공개 근거 없이 “HBM 한 단위가 일반 DRAM CAPA 몇 단위를 대체한다”는 비율을 넣지 않는다. NAND 공정 세대·적층 변화도 곧바로 유효 비트 공급 증가로 환산하지 않는다.

이는 고정된 경기 단계 판별표가 아니다. 예를 들어 가격 상승과 재고 감소가 동시에 관측돼도, 같은 제품·기간·고객군인지와 감산·공정 전환·제품 믹스·수요 변화 중 어떤 설명이 가능한지 먼저 확인한다. DRAM과 NAND, HBM과 서버/모바일 DRAM의 상황을 하나의 “반도체 호황”으로 합치지 않는다.

## 3. 접근 상태를 읽는 법

단계는 **정의됨 → 접근 시험됨 → 관측 저장됨 → 역사·수정 검증됨**으로 구분한다. 한 단계의 완료가 다음 단계를 의미하지 않는다. 아래 지표의 반복·통합 시계열은 새로 수집하지 않았다. 기존 자료의 접근 시험·사건 영수증과 이번 거시 출처 조사를 재사용한다. WSTS의 제한된 시장규모·파일 기준값은 거시 기준판과 출처 영수증에 별도로 기록한다.

- `DEFINED`: 목적·측정 계약 또는 문서상 경로가 정해졌다. 실제 응답·값은 미검증이다.
- `ACCESS_TESTED`: 해당 파일·페이지·소량 응답에 접근했다. 전체 기간·반복 수집 성공은 미검증이다.
- `CASE_SAVED`: 기존 특정 사건·사양·원문 후보가 저장돼 있다. 제품군·분기별 시계열이 아니다.
- `TO_VERIFY`: 정확한 표/태그/SKU/권한/무료 범위 또는 응답이 미확인이다. 결측을 0으로 처리하지 않는다.

아래 “무료”는 표시한 웹·파일·기본 API 경로의 조건이다. 무료 열람, 무료 API, 과거 데이터 제공, 재배포 권리는 별도로 확인한다. 기존 API 보유 여부·키 값·사용자 계정은 공개 문서에 기록하지 않는다.

## 6. 공개 자료로 답할 수 있는 범위와 결합 규칙

무료 우선 순서는 **공식 상품/플랫폼·인증·사건 → 고객/공급사 분기 IR와 공시 → 국가 통계·교역·총 billings → 시설·전력 → 투자자 배분**이다. 가격 전문 데이터나 내부 고객 정보가 없다고 해서 전체 학습 구조를 멈출 필요는 없다. 무료 자료로 어떤 질문까지 답했는지 표시하고, 유료·비공개 공백의 답을 만들어 넣지 않는다.

하이닉스 관점의 첫 비교에서는 HBM·서버 DRAM·eSSD/NAND를 별도 행으로 놓고, 메모리 제품×고객 플랫폼×관측 기간을 기본 키로 쓴다. 모바일·PC를 구조에서 누락하지 않되, 세부 관측 수집의 우선순위와 시장 전체를 구분한다. 다음 필드를 공통으로 보존한다.

| 계약 필드 | 필요한 이유 |
| --- | --- |
| `metric_id`, 원 정의·단위, `product_family/SKU`, `population`, 분류판 | DRAM/NAND, HBM 포함 범위, 다이/모듈/완성장치와 통계 모집단의 혼합 방지 |
| 법인/역할·플랫폼·시설/계약 ID, 연결 근거 | 공급자·기술 검증자·시스템 구매자·사용자와 모회사/자회사의 자동 동일시 방지 |
| `measurement_period`, 사건일, 공개일/정밀도, `known_at`, 목표일, 수집 시각 | 당시 아직 공개되지 않은 정보를 과거 판단에 넣지 않고 전망·실적·사건 분리 |
| actual/guidance/estimate, 계획/건설/운영, capacity/price/accounting basis | 가이던스·능력·생산·판매·현금과 제품 믹스의 단계/정의 차이 보존 |
| source ID·실제 URL·locator·원문 hash·버전·상충/정정 관계 | 원문으로 돌아가고 수정 이력을 보존; 재인용을 독립 자료로 중복 계산하지 않음 |
| missing/suppressed/not-disclosed/access-failed/true-zero | 비공개 물량·유료 범위·실패 응답·0을 구분 |

월·분기·사건 자료를 단순 날짜로 병합하지 않는다. 후속 비교에서 월 자료를 분기로 합칠지, 평균/기말/사건 중 무엇을 쓸지는 **지표별 측정 계약에 먼저 정한다**. 월 지수 평균·재고 기말·분기 누적 CAPEX·사건 수는 서로 다른 연산이다. 누적 공시 금액의 분기 차분도 동일 정의·비교 범위·정정 여부가 확보됐을 때만 한다.

시그널을 평가하려면 당시 알려진 입력과 후속 결과를 분리해 역사 패널을 먼저 만들어야 한다. 공개 시차·정정·제외 사례·대체 설명을 남겨야 한다. 이 문서는 그런 평가를 실행하지 않았으며 H1/Gate 6·Strong Inference·Evidence 상태도 바꾸지 않는다.
